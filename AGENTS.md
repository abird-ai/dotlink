## Shared conventions

These are byte-identical across all abird repositories. Repo-specific rules
follow the markers below.

- **Source of truth.** Live source, tests and executed results outrank dated
  prose. Start at `.agents/plans/README.md` (overview + spec), then work from
  `.agents/plans/TODO.md` (the queue).
- **XDG paths.** Where the project owns user config, data, cache or state,
  resolve it under `$XDG_*_HOME/abird/<project>` — an absolute XDG base, falling
  back to `HOME` when unset. No legacy or alternate root.
- **Shared `.gitignore`.** The block at the top of `.gitignore` is identical
  across repos; repo-specific entries follow it. Keep it mechanical.
- **Preserve other work.** Never revert or overwrite changes you did not make.
- **Owned changes only.** Commit only the paths you changed for the request.
  Before committing, inspect `git diff --cached --stat`; if it lists files you
  did not touch, stop and ask — unless the user explicitly asked you to include
  them.
- **Ownership.** A plan directory belongs to the `@owner` on the queue line, and
  the coordinator alone reconciles `.agents/plans/TODO.md`; do not edit another
  owner's plan or worktree unless the user explicitly asks.
- **Clean pushes.** Do not push from a dirty worktree unless the user explicitly
  asked to include those changes; otherwise commit/stash your own change first,
  or push from a clean temporary worktree.
- **Terse writing.** Keep code comments and docs succinct. Comments need not be
  full sentences; prefer symbols and fragments unless the user asked for an
  explanation or the topic is design-level or otherwise complex. Prefer bullets
  and engineering focus over prose in other docs.
- **Terse output.** Keep replies short and on point, preferably bulleted; avoid
  prose unless the user asked for an explanation. Be terse without dropping
  detail.
- **Git safety.** Commits are signed; never disable signing. Never push,
  force-push, tag, publish, deploy, or run destructive operations — history
  rewrite, `reset --hard`, branch deletion, or touching another agent's staged
  or uncommitted work — without explicit user confirmation for each action. A
  request to "commit" or "apply" is not authorization to push.

## Current invariants

- Config schema is currently **v10**. Compatible older schemas migrate forward only through explicit versioned migration steps (currently v9 → v10); newer schemas and older versions without a defined migration path are rejected rather than guessed. OAuth state is separate from JSONC under the Abird XDG state namespace.
- The launch directory is the internal relative-path base and is read-allowed by default unless `default_allow=false` or `--no-default-allow` is used. An empty-permission saved profile is intentionally valid; `setup::validate_config_structure` checks only persisted structure. `main::Policy::from_args` alone enforces effective minimum capabilities after merging CLI grants and denies (including the readable-directory requirement for shell). `--no-default-allow` and a truly ungranted run must continue failing closed.
- Profile transports start automatically. `--stdio` / `--http` add local transports for one run; `--no-stdio` / `--no-http` / `--no-ngrok` suppress profile defaults. Setup is transactional/default-aware, and `dotlink profile` owns persistent profile mutation. Any externally reachable HTTP is OAuth-protected by default: ngrok is protected automatically, direct non-loopback binds require OAuth + an explicit HTTPS public origin, and only the one-run `--allow-public-no-auth` escape hatch permits unauthenticated public ingress.
- Linux shell execution is Bubblewrap-sandboxed by default. Network is off unless explicitly granted.
- Filesystem denies win over allows. Cache mounts never expand MCP filesystem authority. Deny and protected paths retain lexical and kernel-order resolved identities (`mcp::guard_identities`), including dangling-symlink targets; each sandboxed command re-resolves them. Sandboxed shells reject user binds exposing protected/read-denied paths, including *read-only* binds, and writable binds containing write-denied paths **except for an explicit root read+write grant (`--allow-rw=/`) which intentionally opts out of enforced private-path isolation for the sandboxed shell**. Explicit user denies continue to be enforced and fail if impossible under `/`; network, process and device opt-ins remain independent. Root-mode shell access includes Dotlink-private files by explicit user choice; it does not add ineffective private-path masks. A pathname mask cannot be lifetime-safe against external host renames; even a direct-child deny mount is insufficient. Narrow the shell grants to avoid overlap; native file tools still enforce fine-grained denies. `validate_shell_guards` enforces this for both startup and each call. Masks and deny-write rebinds act on canonical objects; every host bind source is FD-pinned; runtime aliases become sandbox symlinks to one canonical bind. Implicit runtime bind/alias mounts are part of the same read-visibility check for fine-grained profiles; explicit root RW mode intentionally waives that private-path rule. The runtime layout validated by `shell_guards` must be exactly the one used for Bubblewrap assembly. Cache/host/runtime remapping must not bypass denies or protection; deny-write blocks socket/device integrations.
- Linux native file IO must stay descriptor-rooted with openat2 and fail closed on unsupported resolution. Shared traversal errno comparisons use OS-native libc constants, never Linux numeric literals. Directory discovery reads child metadata under the same descriptor and mount-resolution authority as actual opens (Linux `openat2` O_PATH nofollow; macOS `fstatat` plus device check). Pathname metadata or unchecked mountpoint metadata must never be reintroduced after pinning. Linux/macOS native tools are concurrent by default; `-s/--serialize` opts into one-at-a-time MCP calls. Windows retains a conservative operation gate. Never reintroduce pathname IO following authorization for Linux tools.
- Logging is quiet by default: `-v` = TOOL, `-vv` = TOOL + REQ. Interactive non-stdio runs support live `v` verbosity cycling, `V` full-command toggling, and `Ctrl+R` restart; stdio never shares stdin with runtime controls. Runtime controls must snapshot/restore the exact terminal state on every exit/error path. `--quiet -vv` is REQ-only. TOOL logs default to 256 rendered characters for escaped `c="..."`, including quotes and `…` when truncated. `V` permits full, still-escaped commands only while interactive stdin controls **and TOOL logging** are active; hide the key hint and ignore the modifier (without a notice) in quiet/REQ-only mode. Reset full mode when TOOL logging turns off and on shutdown/restart. `p=`, `d=`, and `paths=[...]` must never truncate path names: log all up to 64 distinct valid `edit` paths, without processing more than 512 operations or over-limit file sets. When interactive, with color enabled, style TOOL/REQ keys, values and outcomes separately; do not parse user-controlled log text for fields or put ANSI in noninteractive argument summaries. Keep bulk payloads as byte counts. Format `p`, `d`, `c` before other fields; render paths inside launch cwd as `./...` and outside as `/...` on Unix. Use `max_t`/`max_b` and aggregate payload bytes as `b="N"`. Multi-file `edit` logs bounded, distinct `paths=[...]` relative to the same cwd; the advertised schema has only `edits[].path`, with legacy default paths accepted at decode. The global `MAX_EDIT_OPS=512` and `MAX_EDIT_FILES=64` ceilings in `mcp::tools` govern the wire reader, planner, schema, and log preview. TOOL path labels resolve symlinks best-effort before deciding `./` vs absolute; this never authorizes access. The `MAX_MUTATION_PLAN_BYTES=64 MiB` shared budget applies to `edit`, `patch`, and `bedit`; one shared staged-commit engine and bounded receipt plan keep successful mutating-tool replies within `max_output_bytes` before any commit. `write`/`bwrite` use the same single-result preflight. Match ambiguities use constant-width previews, never unbounded offset vectors. Inline shell secrets in the visible command excerpt, or in interactive full-command mode, can enter journald. Other payloads (file bytes, stdin, patches, grep patterns) remain byte counts. Log scopes and network metadata labels stay bounded/sanitized. Never include control-plane response bodies or malformed protocol payloads in errors; rmcp tracing stays suppressed regardless of `RUST_LOG` because it renders complete MCP payloads.
- Linux KVM/GPU grants are independent opt-ins: vendor-check DRM devices, pin character-device FDs and use Bubblewrap `--dev-bind` rather than regular `--bind-fd`; read-only driver resources must not expand native MCP FS grants. NixOS hardware permissions affect only the corresponding systemd unit.
- Keep stdout protocol-clean for stdio; human output goes to stderr.
- **Intentional open concurrency.** Local HTTP and stdio tool requests have no shared admission/concurrency budget by design; the calling model/client directs parallelism. The OpenAI tunnel's own in-flight bound and per-tool byte/time limits remain. **Do not flag the absence of a global admission cap as an accidental omission in reviews** without a concrete independent issue.
- **Transport body limits:** OpenAI Secure MCP Tunnel has fixed 120 s request and 10 MiB serialized-envelope service limits in `limits.rs`; dotlink reserves 5 s for response delivery, caps complete embedded MCP messages at 9 MiB, and keeps raw/tool transfer ceilings at 8 MiB. `bread` must derive encoding-safe raw windows rather than relying on the outer body limiter. Never rewrite shell execution timeouts to fit a transport response window. Local HTTP request framing may still derive additional JSON/path headroom from profile/tool limits.
- **Mutation lock identity:** `src/mutation.rs` first holds sorted exact-path mutexes for pathname/topology ordering. On Unix it additionally derives one stable target key from the nearest existing ancestor `(dev, ino)` plus the remaining relative target, so lexical/bind aliases of the same directory entry converge on one in-process mutex. Unix ancestor `flock`s are coalesced by directory inode identity (upgrading to the strongest mode) and the opened inode is re-verified before locking; Windows uses native named mutexes plus its conservative operation gate. All guards last through commit and one 30-second deadline spans every local/OS lock. No hash shards or alias-dependent self-flocks.
- **Patch edit grouping and file creation:** `patch::visit_hunk` is the single allocation-free iterator for update-hunk preflight, final output and in-place splicing. Context boundaries split edit groups; match successive added lines to successive removed lines' separators, using the last removed style for excess additions or the actual insertion site for pure additions. Never derive style from an unrelated matched context line. `patch::add_file_line` is the single borrowed decoder for `*** Add File` byte accounting and content assembly, keeping bare and `+`-prefixed CRLF blank lines identical. Preserve both paths; no separate style chooser or duplicated grammar validation.
- **Shared sequence matching:** `mcp::tools::matching::scan_sequence` is the generic linear-time KMP matcher for ordered element sequences. `patch` uses it for exact-first context and trimmed-only-if-no-exact fallback *after* filtering `*** End of File` eligibility, retaining at most ten ambiguity preview positions and scanning in O(source lines + hunk lines) comparisons per pass. Context-free insertion is permitted only with an explicit EOF marker; a bare unanchored `+` hunk must remain rejected. The parser retains each update hunk as one borrowed body span; matching lazily decodes it and retains one `&str` per source-consuming line only after charging that matcher index plus the KMP failure table against the shared scratch plan. Context-only hunks advance the cursor without materializing and splicing an identical replacement vector. Do not recreate nested candidate×context comparisons, add a request-work limit to hide quadratic logic, or conflate two comparison policies.
- **Shared mutations:** `src/mcp/tools/mutation.rs` owns one `PlanBudget` (`MAX_MUTATION_PLAN_BYTES` = 64 MiB), pre-commit `MutationReceipt`, compact single-file replies, bounded serde arrays, and typed `MutationTarget::{Update, Create}` staging/commit used by both `edit` (strict) and `patch` (strict/best-effort). `bedit` shares the ledger and reply preflight, while `write`/`bwrite` precompute bounded success text. Parser limits are enforced at arrival (`patch` 32 sections, `bedit` 32 ranges, `edit` 512 operations/64 files); no stage may begin before response preflight. Match ambiguity scans are bounded diagnostic previews, not unbounded match-index vectors. Keep `largest_fitting_prefix` the single implementation used by listing/search and mutation-receipt trimming.
- **Streaming binary edits and borrowed patch lines:** `bedit` streams file hashing and original-offset replacement through `mutation::{digest_limited, stream_splice}` and the descriptor-rooted `LocalMachine::stage_update_with` writer. A source/result may be up to `min(max_write_bytes, 64 MiB)` without loading both into memory; decoded replacement bytes stay in the shared `PlanBudget`, and the backend rechecks the source SHA-256 before committing. Unix and Windows share staged-producer semantics with mode/DACL protection and cleanup. `patch` uses borrowed `WorkingLine` values for unchanged and added lines, with a trailing-CR flag when an LF patch must insert CRLF; its final assembler emits CR directly, never allocating an owned String per line. Match only real source lines via `split_terminator('\n')`, never the phantom element after terminal LF. Preserve the final newline state separately and remember which CR belongs to a CRLF delimiter (rather than literal content), especially when deleting or inserting at an unterminated EOF. The patch's header fixes LF vs CRLF syntax: a CR in an LF-formatted hunk is literal, while one syntactic CR is removed from CRLF-formatted hunk lines. `LineOutput` defers one line so an unterminated source line can gain a CRLF bridge before a new successor; count that byte in preflight and never strip a literal CR. If the source's unterminated text or a new line's logical content ends in a literal `\r`, append a distinct separator CR before LF to prevent that content byte becoming delimiter syntax. Clearing a former final separator also clears the line's `terminated` metadata for subsequent hunks. For the last mutating hunk, output is assembled directly from borrowed existing/patch lines without expanding the index. Earlier hunks copy only consumed source lines, shift their index with `copy_within`, and write their replacements in place. Both paths use `LineOutput` for final CRLF normalization and preflight output/matcher bytes against the existing plan budget. Do not reintroduce a duplicate replacement-sized Vec, per-line owned strings, or conflate write limits with scratch budgets.
- **Borrowed and low-copy request paths:** `patch` grammar nodes borrow from `PatchArgs.patch`; add-file sections retain one contiguous raw byte range and line/output counts, while each update hunk retains one borrowed body span and decodes lines lazily. Do not reintroduce per-line `String`s or even per-line add-file slice vectors. `Snapshot::verify` compares a pinned source with a 64 KiB buffer instead of reading another whole-file Vec. `edit` changes single matches in place, compacts non-growing `replace_all` using `memchr::memmem`, and keeps earlier replacement texts as borrowed references. HTTP known-tool preflight only deserializes borrowed method/name fields (the rest is skipped), while unknown tools retain rmcp-compatible canonicalization. Embedded OpenAI clones JSON only for unknown tools. Binary decoders consume encoded owned strings promptly; `bedit` proves byte-identical ranges without staging but verifies the current source before returning. Favor these simple shared low-copy primitives over unsafe in-place decoding or independent per-tool buffers.
- **Durable shell jobs / MCP Tasks:** `src/jobs.rs` is the single execution-lifetime owner for ordinary `bash`/`powershell`, native MCP Tasks and `job_start`/`job_list`/`job_get`/`job_output`/`job_ack`/`job_cancel`. Every shell call starts one durable execution; the transport only chooses how long to wait before returning the same handle. `timeout_secs` starts after queue/gate/path+mount preparation and bounds execution, never the response window. Admission + runner registration + shutdown share one manager state lock; tunnel request keys deduplicate side effects. Transport-only request constraints are derived by `ActiveTransports`; sync/result budgets and replay keys are trusted only when a redacted opaque per-runtime capability authenticates the private OpenAI `_meta`. The adapter must clear every preexisting `io.abird.dotlink/*` field before inserting trusted values; public HTTP/stdio lookalikes stay inert. For a hidden OpenAI request, stdout/stderr spools plus terminal metadata are the replay source of truth until terminal delivery is confirmed; failed/expired/ambiguous delivery keeps the request key and spools replayable, while only unambiguous successful delivery retires the key and compacts hidden stream state. Never create a duplicate persisted full task/result artifact. Tool-specific success paths should preflight their semantic result before side effects; `LocalMachine::call_tool` is the final trusted-transport serialized-size postcondition for every tool result and protocol error, truncating oversized error diagnostics explicitly and preserving success status if an invariant unexpectedly leaks an oversized success. Native MCP Tasks must reproduce the original shell `CallToolResult` from leased spools and may be exposed only when that exact result is worst-case safe for the **tightest active transport** sharing the runtime (and the current request); otherwise use the compatibility job surface. Under `--serialize`/Windows, acquire the operation gate before all policy-sensitive shell preparation. Stdout/stderr retain at most 64 MiB each and all retained job state shares the configurable session quota (512 MiB default). `job_output` is pure/replayable and uses reader leases; only idempotent `job_ack` advances cleanup. After full acknowledgement, compatibility spools are deleted and their exposed metadata may be reclaimed under capacity pressure; native-task spools compact to the ordinary-result prefix and retain that prefix until task TTL so exact `tasks/get` remains possible. Filesystem cleanup/compaction failure must remain pending/retryable and must never mark output released prematurely. `job_list` recovers exposed ids. Automatic runtime recovery uses `PreparedMachine` as the one authority snapshot: resolve/pin/validate once, freeze the fingerprint inputs, compare them with the existing session, then construct `LocalMachine` from that exact object with no second authority traversal. Unix/macOS grant identities come from the pinned `SecureFs` root descriptors; Windows authority identity includes native volume/file index. If preparation fails, equality is unproven and the old session must be torn down. Binding intent/policy fingerprints is real release behavior—never hide a required side effect inside `debug_assert!`. Normal teardown cancels+awaits every owned runner; never reintroduce detached create→spawn→attach flows.
- **Low-copy grep pages:** retain the validated source `Vec<u8>` and borrow its UTF-8 view via shared `text_bytes`; do not clone the entire file to String. Discovery retains only `min(MAX_GREP_FILES, max_scanned_files)` lexically best paths (4096 in production), because a path beyond the scan budget can never affect this call. `content` mode collects only the selected hit page (up to 50 indices) and the previous/next match boundary; capture at most 50 × (2 × context + 1) borrowed lines near selected hits in one scan, then render any output-fit prefix from that compact cache. Never rescan a deep source from line 1 for each rejected prefix or allocate a vector for every line/match. Content path labels must stay one record: ordinary UTF-8 names remain plain, grammar-breaking names are JSON-quoted, and invalid-UTF-8 Unix names use explicit byte escapes. `content` budgets raw and escaped MCP-text bytes incrementally while reserving suffix markers; `files`/`count` and `ls` use the shared exact `trim_to_result_budget` prefix fitter. Local transports retain the raw profile ceiling; bounded transports must fit the complete serialized `CallToolResult`. `files`/`count` scan matches with iterators. Preserve hit offset/limit, whole-line truncation, context clipping, and incomplete/work-budget semantics.
- **Local work ceilings are separate:** directory discovery visits at most 100,000 entries; grep reads at most 32 MiB across 4,096 candidate files per call and reports incomplete coverage. Paged `read` limits actual source I/O to 32 MiB before its requested line offset, including buffered prefetch. Opt-in `.gitignore` scans fail explicitly above 64 KiB/1024 lines per ignore file or 4 MiB/256 non-absent file reads per walk; failed reads charge partial bytes, and denied rules are not read or charged. Denied/unreadable `.gitignore` rules are distinct from absent files, and surface `ignore_rules`; compatibility `incomplete_reason` reports the first cause while `incomplete_reasons` retains every concurrent cause. The same shared walker flags unreadable subtrees and metadata as `traversal_error`, and grep flags unreadable discovered candidates; explicit filtering remains intentional. Text tools share UTF-8/binary-control classification; byte-oriented work belongs to the binary tools.
- **Unsandboxed Unix shell:** cleanup kills the command's process group; `setsid` descendants may escape. Only Bubblewrap provides the default stronger PID-namespace lifecycle. Do not claim all unsandboxed descendants are contained.
- **Failure recovery:** `recovery::Recovery` is the one failure taxonomy (`Runtime` in-process restart, `Process` default, `Operator` = exit `CONFIG`/78, `Unconfigured` = exit `NOTCONFIGURED`/6, which is not a failure: first-run setup is still pending, so a supervisor stops cleanly). Classify at the source and never by elimination. `Operator` covers planning content (`recovery::config_failure`; I/O-caused planning errors restart), sandbox policy the shell cannot enforce and out-of-range limits (tagged in `LocalMachine::new`), and OpenAI key/tunnel rejections that persist for the confirmation window (60 s); one 401/403/404 keeps retrying. The process-wide `openai::RejectionLedger` keeps that window across in-process runtime restarts until an accepted poll or a changed tunnel identity. Unreadable or absent explicit credential files restart. Unclassified or lost tags restart the process; cleanup failures override the primary class; one-shot commands and clap usage errors keep their conventional exit codes (1 and 2). Under NixOS, systemd 255 or newer uses `Restart=always` plus `RestartPreventExitStatus=2 CONFIG NOTCONFIGURED` and `SuccessExitStatus=NOTCONFIGURED`: exit 0, clean signals and all failures except 2/78 restart after 2 s doubling to 10 min, while an unconfigured service goes inactive as a success, and explicit stop/restart jobs remain authoritative. There is no start fuse; OOM handling stays at the systemd default. Ten minutes of uptime send `RESTART_RESET=1`; systemd 255–257 warn because only 258 or newer applies it. Ctrl+C and SIGTERM latch once for the process (`shutdown::Shutdown`), so a signal is never lost across runtime restarts. Supervisor variables are captured and removed before threads start; credential variables are hidden from every child via `credentials::hide_from_child`.
- **Credential lifecycle:** --print-id and --list-tools are configuration-only: neither may read Runtime keys, initialize transports, host services or private state. Resolve explicit env/file credentials before reading a saved Runtime key; active file credentials are read once and carry their descriptor-verified protected target into runtime construction. Never open dormant OpenAI/ngrok credential files. Active saved credentials fail closed when unusable, but explicit overrides and profile management/replacement remain recoverable. Credential generations are pruned only after durable rotation, retaining selected/prior generations through unrelated edits; interrupted deletion remains retryable. A running OAuth server selects the current committed owner generation on each password check, including a post-verify selection recheck; deleting a saved profile never falls back to legacy. Token/code validation precedes consumption; authorization-code redemption uses a short claim without holding its mutex across durable I/O, and temporary store failures return retryable HTTP 503 without burning the code. Argon2 workers retain permits after request cancellation until their uncancellable OS work exits; CIMD uses cancellable async system DNS, so timeout/cancellation releases its full lease immediately; missing system DNS disables CIMD without blocking registered-client OAuth. Public token exchanges have bounded admission and never hold the access-token mutex during durable state work; access-token poison recovery is consistent across publication/validation/revocation, and revocation has no anonymously exhaustible rolling-minute quota. A version-checked read-only index of refresh grants and registered DCR clients rejects definite unknown grants before expensive state work without rejecting fresh cross-process grants; contention/version races fall through to authoritative work, while stable malformed state returns retryable unavailability without repeated parsing. Public OAuth client IDs have separate DCR and HTTPS CIMD namespaces; public errors never expose private control-plane file paths or parser details. Private control-plane files use symmetric read/write ceilings through `bounded` (OAuth 16 MiB, profiles 4 MiB, credential files 16 KiB); serialize and validate before replacement, and reject Unix special files without blocking. Windows OAuth state cache invalidation uses native file identity, not timestamps alone. Pending OAuth clients/authorizations use shared non-evicting admission with every redirect/client share, a four-entry requester-within-redirect/client share, an eight-entry overall trusted-requester share, and explicit 429s. Trusted requester identity comes only from the direct TCP peer or authenticated ngrok tunnel metadata: ports are ignored, mapped IPv6 normalizes to IPv4, IPv6 groups by /48, loopback is one local identity, and forwarded headers remain untrusted. Owner consent POST claims remain reserved through async verification and automatically release on cancellation; password work admits six rolling-minute starts per trusted requester under two global workers, charges both consent-creation and POST source identities, and never evicts active requester history; terminal success/denial or expired/full DCR promotion consumes exactly once, while transient storage failures preserve the claim. Authorization-code, access-token and refresh-grant capacity prunes only expired entries and never evicts live grants; access tokens also have a per-client share, failed issuance preserves the original credential, and an authoritatively revoked DCR client consumes its terminal code. Untrusted client display names neutralize control, line-separator and bidi characters before UI/terminal output. CIMD admits at most two in-flight and 12 rolling-minute starts per requester plus four process-wide; its bounded requester table never evicts live history, and private literal IPs are rejected before admission. Pending owner authorization retries share one bounded insertion/recovery path. One outer Host allowlist covers MCP and every OAuth route, normalizes mapped IPs, returns 400 for malformed/conflicting authorities, and trusts only exact configured public/listener authorities. SEP-2243 HTTP/OpenAI calls reject unknown policy tool names before rmcp's negative schema cache; network preflight shares the exact request-body ceiling. Ngrok connections are served directly with their authenticated edge peer metadata; no forwarding header or loopback proxy establishes identity. HTTP route futures cancel first, accepted IO force-closes at the drain bound, and bounded ngrok tunnel/session close completes before restart; a drain timeout is a cleanup failure, and cleanup failure takes precedence over restart requests to prevent replacement-runtime overlap. Shell progress notification backpressure must not cross process deadlines.

## Validation before commit

```bash
cargo fmt --check
cargo test --locked --all-features
cargo clippy --locked --all-targets --all-features -- -D warnings
git diff --check
alejandra --check flake.nix nix
markdownlint-cli2
```

Use `nix develop` for the pinned Rust, Alejandra, and Markdown lint tools.
`nix flake check` runs the reproducible build, test, and lint checks together.

For sandbox-affecting work, also run `DOTLINK_TEST_BWRAP=1 cargo test --locked --all-features`.
For a machine with configured GPU drivers, optionally run
`DOTLINK_TEST_BWRAP=1 DOTLINK_TEST_GPU_SMOKE=1 cargo test --locked --all-features discovered_gpu_and_kvm_nodes_are_visible_only_when_granted`
to exercise actual `nvidia-smi` and `vulkaninfo` within Bubblewrap (when installed). Profile/setup changes should also smoke `dotlink profile` lifecycle/mutations and transactional setup cancellation. For release/build changes, run the Nix flake checks and relevant dist outputs.

Do not weaken permissions, sandboxing, credential masking, or transport isolation to make a test pass.
